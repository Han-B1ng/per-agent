

## 4. 规格缺口拍板单（场景 + 可选口径）

1. **状态变更协议**（已按临时协议实现）：items[] 用 op+稳定 id（confirm_event/deny_event/delete_event/complete_task/delete_task/add_*）。场景：同名任务完成其一、一轮两条 pending 确认其一。可选口径：A 维持 op+id（现状）；B 改为模型只回自然语言、客户端本地匹配 id（歧义风险高，不推荐）。当前注入 openTasks/pendingEvents 带 id，模型引用未知 id 直接丢弃。
2. **同日排序键**（已按 createdAt+id 实现）：场景：同日补录旧日期后排序稳定。可选口径：A createdAt 录入序（现状，补录会排到当日末尾）；B 增加显式 seq 字段由用户/模型指定发生序（更准但增采集摩擦）。
3. **明细三段式**（已实现）：原始→涨跌停调整→实际，逐日展示并对上收盘（`p0-limit-up.png`）。无待决。
4. **逾期上限数值**：见 §3，需给单任务累计上限（现 0.02）或改为每日上限口径。
5. **rest 是否打破沉默 / paused 是否计逾期**：见 §3，现 rest 打破、paused 不计；若改口径仅动 engine 两处。
