## 2. 模块责任与数据流

- `web/app.js`：三入口导航、行情专注模式、对话、目标/记录视图与统一详情抽屉。
- `web/ledger.js`：唯一业务写入口 `applyItems`；目标与成长记录派生查询；稳定 ID 关联；完成幂等；修正/撤销审计。
- `web/store.js`：`pe.personal.v2` 持久化；读取并迁移 P0 `pe.personal.v1`；样例不写存储。
- `web/engine.js`：未改算法，继续从同一账本全量重算日/周 K，执行 D18–D40。
- `web/chart.js`、`web/sample-data.js`、`web/extractor.js`：复用周 K、只读样例和同源抽取客户端。
- `server/`：本地静态托管、OpenAI 兼容代理与 Mock；`functions/`：Sites Function → Cloud Agents CN。
- 数据流：页面或聊天动作 → `ledger.applyItems` → v2 持久化 → 目标/记录派生查询 + `computeAll` → 三页面、聊天卡和明细同步渲染。

## 3. 数据契约与迁移

- v2 结构：`{version:2, events:[], rests:[], tasks:[], chat:[], audit:[]}`。业务事实仍只有 events/rests/tasks；audit 只存变更轨迹，不参与计分。
- 首次读取 v1 时写入 v2，并保留 v1 作为回退副本；「清空我的记录」同时删除 v1/v2，避免旧数据复活。样例不受影响。
- 已实测 v1 的普通行为、pending 休息、已完成任务和暂停任务均可读出。
- 任务完成只修改原任务的 `status/doneAt`，成长记录派生一笔 `completion`，不新增 behavior event。重复完成返回 `changed:0`。
- 确认、否认、修正、撤销均按稳定 ID 走同一动作入口；原文和关联 ID 保留，修正确认日期后全量重算，撤销项可通过「显示已撤销」追溯。

### 暂停 / 恢复 / 改到期日（本轮不开放编辑，待负责人定口径）

具体案例：任务到期日为 **2026-11-10**，2026-11-11 起已产生逾期扣分；2026-11-15 暂停，2026-11-18 恢复，或 2026-11-15 把到期日改为 2026-11-25。需拍板：① 11-11～11-14 已结算扣分是否保留；② 11-15～11-17 暂停期是否计逾期；③ 改期后 11-15 起按旧到期日、新到期日还是保留旧窗口并重起新窗口。v0.2 仅展示既有 paused 状态，不提供暂停、恢复或改期按钮，不擅自改变历史计分。
