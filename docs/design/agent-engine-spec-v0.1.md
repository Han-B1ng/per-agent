## 0. 不可动摇的已定项（来自 decision-log，不重新讨论）

- 模型只抽取结构化事件/任务，绝不口算分数（D11）
- 引擎是前端纯函数：确定性、同输入同输出、可离线复算（D11）
- 每根 K 线可点开计算明细（事件原文引用 + 权重 + 贡献点数）
- 主图周 K 线，日/周/月可切换；图表前端渲染（D6/D7）
- 一次对话返回即更新指数与图（D8）
- 沉默（连续无事件）→ 指数缓慢衰减（D15；衰减率与休息边界已定，见 D20–D24）
- 抽取低置信度 → 追问确认后再计分（D16）
- 数据默认只存浏览器本地；后端仅一个模型代理 function，Key 只在 Sites Secret
- 纠错/撤销 = 软删除事件 + 全量重算

## 1. 情绪是否计入指数 —— 用户已定（D18）

**情绪表达记录但不计分。**

- 情绪表达（如「今天很焦虑」「好开心」）抽取为 `polarity = neutral` 的情绪事件：进事件流、可被计算明细引用、供 agent 共情回应，**不产生任何分数**。
- 情绪引发的**行为**（如「因为焦虑刷了 3 小时手机」「心情好去散步了」）按行为事件正常抽取与计分，计的是行为不是情绪。
- 理由：指数只度量行为（价值观硬约束）；一旦难过就扣分，用户不敢说真话，采集失真，「被度量」立意塌掉。
- 对 schema 的影响：事件需要能区分「情绪表达」与「行为」，字段设计见开放项 6。

## 2. 维度划分 / 板块 —— 用户已定（D19）

**无板块，只有总指数。**

- 指数只有一个总分，不做板块指数、不做雷达图。
- 事件不带 `dimension` 字段；可带自由 `tags` 供筛选与事件流展示，tags 不参与计分。
- 设计稿中随之失效的部分：§3 隐喻表「板块」行、§4.2 `dimension` 字段、§4.3 `dimensionWeight` 与「板块指数」行、P1「板块雷达」。
- 公式起点相应简化：事件影响% = sign(polarity) × base[intensity]（权重数值仍待校准，见开放项 4/设计稿 P4）。

## 3. 沉默衰减与休息 —— 用户已定（D20–D24）

**已定口径：**

- **主动标记休息 = 停牌**：停牌保护期 **7 天**，期内不衰减且**每日 +0.05%**（7 天封顶，一段休息最多 +0.35%）；第 8 天起保护失效，开始衰减（D20/D23/D24）。
- **被动沉默**（既不说话也不标记休息）：连续第 4 个无事件日起，每日 **-0.1%** 衰减（D22）。连续 30 天约跌 3%。
- **超过停牌期限后的衰减率与被动沉默相同**：-0.1%/天，引擎只有一套衰减逻辑（D23）。
- **任何事件都打破沉默**，包括 neutral 情绪表达（D21）。倾诉不算沉默，保护采集真实性，与 D18 一致。打破沉默会重置连续计数（休息/沉默的连续性均以「无事件日」计）。
- 衰减与停牌加分都计入当日 r，参与涨跌停 clamp 与明细展示（明细标注来源「沉默衰减」/「停牌恢复」，无 quote）。
- 设计稿「连续休息 ≥ 2 天一次性 +0.3%」被 D23 的「停牌期内每日小加分」取代。

**待定细节：** 无（开放项 3 关闭）。

## 4. 防刷 —— 用户已定（D25–D27）

**已定机制与阈值：**

- **完成增益不双重计分**：完成任务只产生完成增益（+0.6% × position/3，数值属权重校准范围），不再额外建 positive 事件（D25）。
- **完成逾期任务的历史保留（D39，用户 2026-11-17 定稿口径 A）**：逾期损耗按「历史窗口」重建、与任务当前状态解耦——open 任务计至今天，done 任务计至 `doneAt−1`；**完成当日只计一次完成增益、不再计当日逾期**；完成前已结算的逾期扣分与历史收盘在完成后保持不变。单任务累计逾期上限仍属权重校准范围（P4）。
- **单日涨跌停 ±6%**：当日 r 被 clamp 在 [-6%, +6%]（D26，确认设计稿 v0.1 起点）。
- **同日计分事件上限 8 条**：超出部分只记录不计分——进事件流、明细可见但贡献为 0，明细标注「超出当日上限」（D27）。无板块（D19），上限为全局。
- **明确不采纳**：语义去重、同极性边际递减（D27）。防刷靠「不双重计分 + 8 条上限 + ±6% 涨跌停」三层兜底。

**引擎事件处理顺序（规格口径，供实现会话消费）：**

1. 软删除事件不参与计算（已定：纠错 = 软删除 + 全量重算）
2. 当日事件按发生顺序取前 8 条计分，其余贡献记 0
3. 情绪事件（D18）贡献恒为 0，不占 8 条计分名额
4. 完成任务只计完成增益（D25）；逾期损耗按历史窗口计至完成前一日（done 任务 `dueAt+1..doneAt−1`），完成当日不计逾期（D39）
5. 汇总当日 r → clamp ±6% → 更新指数

## 5. 推演 —— 用户已定（D28）

**接受助手提案口径：**

- 输入：近 28 天日收益率 → 均值 μ、标准差 σ；持仓中未来 28 天内到期任务的完成增益之和（Σ 0.6% × position/3）。
- 中性：当前指数 × (1+μ)^28 + 持仓贡献。
- 乐观/悲观：中性基础上 ±1σ 按随机游走口径传播 28 天（σ×√28），区间随时间展宽。
- 样本 < 4 周：降级为仅给方向（上行/持平/下行），不给具体点位。
- 硬约束：界面必须标注「这是推演，不是预测」，显示不确定性。
- 推演也是前端纯函数（同输入同输出），不经过模型。
- 优先级仍为 P2（有余力再做），但口径已定，实现时不再讨论。

## 6. 抽取 schema —— 用户已定（D29–D32）

**已定规则：**

- **confidence 为数值 0–1，< 0.6 触发追问确认后再计分**（D29，落实 D16）。追问期间事件暂存为 pending，不计分；用户确认后转正，否认则软删除。
- **时间归一化**：抽取时注入当前日期；相对时间词（昨天/上周三）转 ISO；定不下来的默认今天并标低置信度（自然触发追问）（D30）。
- **主动标记休息由对话抽取**：「今天休息/请假/摆烂一天」→ 模型抽取为休息标记；误判风险由置信度追问兜底（D31）。不做 UI 按钮。
- **一句话多意图 → JSON 数组多事件**：「跑了 5 公里，论文写完了，就是有点累」→ 2 条行为 + 1 条情绪（D32）。

**Schema（由已定决策推导）：**

```json
// 事件
{
  "id": "evt_xxx",
  "kind": "event",
  "eventType": "behavior | emotion",
  "polarity": "positive|negative|neutral",
  "intensity": 1,
  "occurredAt": "2026-11-16",
  "quote": "今天跑了 5 公里",
  "tags": [],
  "confidence": 0.9,
  "status": "pending | confirmed",
  "deletedAt": null
}
// 休息标记
{ "id": "rest_xxx", "kind": "rest", "date": "2026-11-16", "quote": "今天摆烂", "confidence": 0.9 }
// 任务（持仓）
{
  "id": "task_xxx",
  "title": "写完论文第三章",
  "dueAt": "2026-11-25",
  "position": 3,
  "status": "open|done|paused",
  "createdAt": "2026-11-16",
  "doneAt": null,
  "deletedAt": null
}
```

**引擎侧推导（确定性要求，非模型职责）：**

- `overdue` 不由模型判断：引擎按 `dueAt` 与当前日期推导，逾期损耗按设计稿公式（每日计、设上限，上限值属权重校准范围）。**按历史窗口重建（D39）**：open 任务 `dueAt+1..today`；done 任务 `dueAt+1..doneAt−1`，完成后保留历史扣分；完成当日只计完成增益、不计逾期。
- 情绪事件（eventType=emotion）polarity 恒为 neutral、贡献恒为 0、不占同日 8 条计分名额（D18/D27）。
- pending 事件/休息不计分；**且不得提前账本起点、不得触发沉默衰减或停牌增益**（起点与沉默只由 confirmed 记录决定，D29 隔离口径）；软删除（deletedAt 非空）事件不参与计算；全量重算时一律重放。
- 模型输出永远不含分数字段——schema 里没有 score，职责切分（D11）在结构上强制。

## 7. 回复策略 —— 用户已定（D33）

- **先接住情绪，再轻量确认录入**（如「记下了」「这条进今天的走势了」），**不报具体点数**。
- 数字变化交给图自己说话（「说一句，图就动了」），对话保持陪伴感，不做报分机器。
- 硬约束不变：下跌文案永远是「波动」，不是「你不行」；不评判人格。
- 低置信度追问（D29）是例外场景：此时必须明确问「这是什么时候的事 / 是不是这个意思」，确认后再计分。

## 8. 上下文与成本 —— 用户已定（D34–D36）

**已定口径：**

- **固定注入**（每次调用）：当前日期时间 + open 任务列表（title/dueAt/position）+ pending 待确认事件（D34）。
- **滚动窗口**：最近 **10 轮**对话，供情绪上下文与代词指代（D35）。**不注入全量事件历史**——历史在本地存储，引擎全量重算；注入模型徒增 token 与隐私暴露。
- **单次调用**：一次模型调用返回 `{reply, items[]}`，回复与抽取一起出（D36）。成本最低、延迟最小，保「说一句，图就动了」。
- 成本控制沿用设计稿 §9：同一句话抽取结果缓存、限频、熔断降级到预置样例数据（绝不白屏）。
- 隐私告知不变：调用模型时内容会发给模型服务，需明确告知用户。
