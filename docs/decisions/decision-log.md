> 来源：验收会话发现②③。属技术协议设计，由 agent 逻辑专项会话敲定后写入 agent-engine-spec。

| 缺口 | 说明 | 验收用例 |
| --- | --- | --- |
| 状态变更协议 | 注入上下文须带稳定 id（task.id / pending event.id）；items[] 定义结构化操作（confirm_event/complete_task/delete_event 等），引用一律用 id 不用 title；同名任务/多条 pending 歧义时强制追问 | 同名任务完成其一；一轮两条 pending 确认其一 |

## 已排除的方案（不要回头捡）

| 方案 | 排除原因 |
| --- | --- |
| 3D 可拆解手工坊 | 单人 14 天风险过高 |
| 课件变知识图谱 | 同类作品已多，差异化不足 |
| 真 24h 主动推送 | 需定时触发 + 通知通道，易吞掉一周；改用交易日节律 |
| 账号体系 / 登录 | 与「评委点开即用」冲突 |
| 排行榜 / 社交比较 | 把自我度量变成攀比，价值观风险 |
| 模型口算指数 | 分数会飘、不可解释，立意塌掉 |
| 普通折线图代替 K 线 | 丢掉「炒股软件」视觉落差，记忆点消失 |
| API Key 写进前端 | 公开站点必被盗用刷爆账单 |
| 玄学式命运预测 | 评审减分，涉及心理状态有伦理风险 |
| 「左聊天 / 中图 / 右面板」三栏 | 助手自行提出，非用户意图；已被 D13 的 Codex/Qoder 式三区壳取代 |
